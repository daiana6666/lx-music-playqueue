本计划以手机端为主要实施项目。只有数据协议、备份格式和互通行为需要配合时，才修改桌面端。每个阶段完成后交付可安装、可验证的 Android 构建；阶段验收通过后进入下一阶段。

## 1. 基线与目标

| 项目 | 本次对照的代码基线 | 路径 |
| --- | --- | --- |
| 桌面端 | `130a4190`，2026-09-08，版本 3.0.0 | `D:/projects/lx-music-desktop` |
| 手机端 | `379106c`，2026-07-23，版本 2.0.0 | `D:/projects/lx-music-mobile` |

手机端已有网易云登录与推荐、私人 FM、喜欢同步、最近播放存储、听歌时长、本地音乐导入、WebDAV 播放、一起听、自定义源导入及推送／拉取。后续开发在这些实现上扩展。

目标包括两部分：

- **功能迁移**：让手机端具备桌面端新增的核心使用能力，交互按手机屏幕和 Android 后台运行方式实现。
- **数据互通**：让歌单及需要共享的资料、源脚本及其来源信息在两端传递时保留含义，并兼容已有客户端。

最近播放和统计的功能对齐，默认采用各设备分别记录的方式。跨设备合并播放历史、合并统计总量属于后续扩展，需要设备事件去重和冲突协议，不能用总数相加实现。

本次前序对照已运行手机端 48 项逻辑测试、桌面端 24 项同步兼容测试，均通过。这是代码基线证据；真机扫码、播放及两端联网联调仍需在实施时完成。

## 5. 第三阶段：播放可靠性与存储

- [x] 为歌单、资料、最近播放、统计和设置明确版本与读写接口，准备升级前可恢复的数据副本。

- [x] 将用户数据、可重建缓存和临时文件分开，明确各项清理操作的范围。
- [x] 制定迁移重入、失败恢复和旧数据保留规则；升级失败时回到仍可读取的原状态。

- [x] 使用界面无关的接口封装运行器，让备用源逻辑不依赖 Electron 窗口机制。

**验收**：A 源初始化或运行失败不污染 B 源；删除源后旧回调不会完成新请求；前后台切换及连续切歌无持续增长的实例和悬挂请求。

### P3-03 主源与有序备用源

- [x] 对齐桌面的歌曲候选匹配、源能力、请求超时、失败分类和取消规则。
- [x] 复用统一会话协调当前播放与下一首预加载，忽略被替换歌曲的迟到结果。
- [x] 将媒体可用性验证接入 Android 播放器，验证通过后再提交可复用 URL 缓存。

- [x] 在 URL 结果、缓存、播放器状态和播放栏之间传递返回音质及已验证播放状态。

## 7. 数据同步边界

| 数据 | 本计划中的方式 | 关键规则 |
| --- | --- | --- |
| 普通歌单与歌曲 | 保留双向同步 | 兼容已有合并／覆盖及快照规则 |
| 分组、简介、封面引用 | 第一阶段增加可选资料同步 | 旧客户端缺字段不表示删除；本地文件路径不可直接跨设备使用 |
| 自定义源脚本及 GitHub 来源信息 | 第一阶段完善双向往返 | 保留来源字段及手机独有脚本，更新失败时保留原状态 |
| 平台账号歌单 | 第二阶段由各设备登录后拉取 | 稳定 ID 去重；同步得到的资料不能代替本机账号授权 |
| 账号凭据、WebDAV 密码、同步密钥 | 各设备安全存储 | 通过各自登录或配置建立，不作为普通同步字段 |
| 最近播放、听歌时长及次数 | 各设备记录，支持本机备份恢复 | 本计划不自动合并两台设备的总量 |
| 当前播放状态 | 延续一起听会话 | 会话同步与持久化历史使用各自的规则 |
| 主源与备用源偏好 | 第三阶段先按设备保存 | 设备上不存在的脚本不能因远端设置成为活动源；跨设备偏好同步另行扩展 |
| 播放 URL、图片、歌词原始缓存 | 各设备管理 | 可重建，避免传播过期 URL 或账号相关缓存 |
| 本地音频文件 | 导入、上传／下载处理 | 普通歌单同步只传元数据，不负责搬运文件 |

桌面端的 `CURRENT_SYNC_PROTOCOL` 与 `LEGACY_SYNC_PROTOCOL` 均已有实现。第一阶段先验证当前组合的兼容行为，新增资料能力采用协商，不把更换身份字符串当成互通的必要前提。

## 9. 验证与交付规则

### 每个任务

1. 更新任务状态，列出改动文件、输入输出及需要保留的旧行为。
2. 对计数、取消、数据合并、迁移和协议等有行为风险的逻辑增加对应测试；样式及文案调整采用界面验证。
3. 运行相关检查。失败时修复或记录能够复现的外部阻塞，不把缺少真机测试写成已通过。
4. 在任务记录中附上对应提交、验证结果及未完成项。

### 每个阶段

- 手机端运行 `npm run test:logic`、`npx tsc --noEmit` 和 `npm run lint`。
- 涉及桌面代码时运行其相关模块测试、类型／构建检查。同步协议变更继续运行 `scripts/test-sync-client-compatibility.js` 和 `scripts/test-sync-rpc-wire-compatibility.js`。
- Android 构建从项目的 `android` 目录运行 `./gradlew.bat assembleDebug`；正式交付使用配置好的 Release 构建并完成安装验证。
- Bundle 检查使用临时输出目录。项目现有 `build-test` 会写入根目录 `index.android.bundle` 和 `res/`，实施时应检查产物差异，避免把临时验证文件混入功能提交。
- 真机验证覆盖冷启动、升级安装、前后台、熄屏、网络中断、字体缩放；账号和双端功能另外执行对应联调。
- 阶段交付记录包含构建对应的提交号、APK 路径、测试结果、兼容限制及恢复方式。未经实测的设备或平台不列为已支持。

### 双端联调最小集合

| 场景 | 预期 |
| --- | --- |
| 当前桌面与当前手机连接 | 基础列表、源同步和一起听正常；验证旧身份兼容路径 |
| 升级一端，另一端保持旧版 | 原有能力可用，新字段不会造成旧数据被清空 |
| 双端均升级 | 新资料能力协商成功，数据可以往返 |
| 离线后两端分别修改 | 根据快照与选定方向处理冲突，保留可恢复数据 |
| 同一平台切换账号 | 旧请求失效，新的目录和播放缓存使用新账号边界 |
| 源脚本被替换或删除 | 活动配置、候选会话和缓存相应更新，已取消请求不能复活 |
